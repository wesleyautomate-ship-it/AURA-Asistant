# Aura v2.8.1 - UX Refinement & Transcription Mode Toggle

## Overview
This minor release fixes the bottom navigation overlap issue on the Requests page and adds a flexible transcription mode toggle for development and production environments.

---

## Changes

### 1. Fixed Bottom Nav Overlap
**Problem:** Bottom navigation bar was covering the last request item on mobile devices.

**Solution:**
- Added `pb-24 sm:pb-20` padding to Requests page root container
- Ensures last item remains fully visible with comfortable spacing
- Responsive: 6rem (24 units) on mobile, 5rem (20 units) on desktop

**File:** `src/pages/Requests.tsx`

---

### 2. Transcription Mode Toggle

**Problem:** All users forced to use backend API for transcription, causing:
- Slower development/testing workflow
- Dependency on backend availability
- No graceful degradation option

**Solution:** Runtime toggle between mock and real transcription modes.

#### Environment Variable
Added to `.env.example`:
```env
# Transcription Mode
# Set to 'true' to use real voice transcription via backend API
# Set to 'false' to use mock transcriptions (faster, no API required)
VITE_USE_REAL_TRANSCRIPTION=false
```

#### Mock Transcription Function
Created `generateMockTranscription()` with 8 Dubai-focused sample transcriptions:
- CMA for Downtown Dubai
- Marketing campaigns for Palm Jumeirah
- Sales data analysis for Dubai Marina
- Property valuation reports
- Social media content generation
- Buyer presentations
- Commercial property trends in Business Bay
- Investment analysis reports

**Features:**
- Random selection from pool
- 800ms simulated API delay for realistic UX
- No backend dependency

#### Real Transcription Mode
When `VITE_USE_REAL_TRANSCRIPTION=true`:
- Uses actual backend API `/api/v1/voice/transcribe`
- Sends audio blob via FormData
- Full error handling
- **Automatic fallback to mock** if API fails

#### Console Logging
Enhanced logging with `[Transcription]` prefix:
- `[Transcription] Using mock mode`
- `[Transcription] Using real API mode`
- `[Transcription] API error: [details]`
- `[Transcription] Falling back to mock mode`

**File:** `src/services/api.ts`

---

### 3. Mode Indicator in UI

Added subtle indicator below status text in Command Center:
- Shows current transcription mode
- **Mock:** "⚙️ Mock transcription"
- **Real:** "🎙️ Real transcription"
- Styling: 10px font, gray color, center-aligned
- Non-intrusive but always visible

**File:** `src/components/ui/CommandCenter.tsx`

## Usage Guide

### Development Mode (Default)
No configuration needed! Default is mock mode:
```bash
# .env (or no .env file)
VITE_USE_REAL_TRANSCRIPTION=false
```

Benefits:
- ✅ Fast testing (800ms mock delay vs 1-2s+ API call)
- ✅ No backend required
- ✅ Works offline
- ✅ Predictable Dubai-focused samples

### Production Mode
Create a `.env` file (or `.env.production`):
```bash
VITE_API_BASE_URL=https://api.your-domain.com
VITE_USE_REAL_TRANSCRIPTION=true
```

Benefits:
- ✅ Real voice input from users
- ✅ Authentic transcription results
- ✅ Automatic fallback to mock on errors

### Switching Modes
1. Update `.env` file
2. Restart dev server: `npm run dev`
3. Check indicator in Command Center UI
4. Test voice recording

## Testing

### Test Mock Mode
1. Ensure `VITE_USE_REAL_TRANSCRIPTION=false` (or unset)
2. Open Command Center → Voice mode
3. Click mic → Stop recording
4. **Verify:**
   - Console shows `[Transcription] Using mock mode`
   - Transcription appears within ~1 second
   - Text is one of the 8 Dubai samples
   - Indicator shows "⚙️ Mock transcription"

### Test Real Mode
1. Set `VITE_USE_REAL_TRANSCRIPTION=true`
2. Start backend server on port 8000
3. Restart frontend dev server
4. Open Command Center → Voice mode
5. Click mic → Stop recording
6. **Verify:**
   - Console shows `[Transcription] Using real API mode`
   - API request sent to backend
   - Real transcription result displayed
   - Indicator shows "🎙️ Real transcription"

### Test Fallback
1. Set `VITE_USE_REAL_TRANSCRIPTION=true`
2. **Stop backend server**
3. Try voice recording
4. **Verify:**
   - Console shows `[Transcription] API error: ...`
   - Console shows `[Transcription] Falling back to mock mode`
   - Mock transcription still works
   - No app crash

### Test Bottom Nav Fix
1. Navigate to Requests page
2. Create 5+ requests to fill the list
3. Scroll to bottom
4. **Verify:**
   - Last request fully visible
   - No overlap with bottom nav bar
   - Comfortable spacing below last item

## Troubleshooting

### Indicator Not Showing
- Check Command Center is in Voice mode
- Verify dev server restarted after .env changes
- Look below the status text (small gray text)

### Mock Transcriptions Not Working
- Verify `VITE_USE_REAL_TRANSCRIPTION` is `false` or unset
- Check browser console for `[Transcription] Using mock mode`
- Restart dev server

### Real Transcription Not Working
- Verify `VITE_USE_REAL_TRANSCRIPTION=true` in .env
- Check backend is running on correct port
- Verify CORS settings allow frontend origin
- Check browser console for API errors

### Bottom Nav Still Overlapping
- Clear browser cache
- Hard reload (Ctrl+Shift+R)
- Check mobile viewport size
- Verify `pb-24 sm:pb-20` classes applied to root div

## Developer Notes

### Why Mock by Default?
- Faster development cycle (no API latency)
- Works without backend running
- Predictable results for UI testing
- Reduces API costs during development

### Why Not Just Remove Mock?
- Mock mode valuable for:
  - Offline development
  - Demo environments
  - UI/UX testing without backend
  - Faster CI/CD test runs

### Implementation Pattern
This pattern can be replicated for other features:
```typescript
const useRealFeature = import.meta.env.VITE_USE_REAL_[FEATURE] === 'true';

if (!useRealFeature) {
  return mockImplementation();
}

try {
  return realImplementation();
} catch {
  return mockImplementation(); // Graceful fallback
}
```
