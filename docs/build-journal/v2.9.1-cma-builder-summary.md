# Aura v2.9.1 - CMA Builder Integration

## Overview
This release connects the CMA intent detection to actual report generation, attaching downloadable PDF links to completed requests.

---

## Problem Statement
**In v2.9:** CMA intents were detected and routed, but no actual report was generated. Users had no way to access the resulting CMA document.

**In v2.9.1:** When Aura detects a CMA request, it automatically generates a market report and provides a download link in the Requests page.

---

## Solution Architecture

### 1. CMA Report Generation (`src/services/workflowApi.ts`)

**Added Functions:**
- **`mockCMAReport(location)`** - Generates mock CMA for development
  - 1.2 second simulated delay
  - Returns mock PDF URL: `/mock-reports/CMA_Downtown_Dubai_1234567890.pdf`
  - No backend required

- **`generateCMAReport(location)`** - Main CMA generation function
  - Checks `VITE_USE_REAL_API` environment variable
  - **Mock Mode (default):** Uses `mockCMAReport()`
  - **Real Mode:** Calls `POST /api/v1/cma/report`
  - **Graceful Fallback:** If real API fails, falls back to mock

**API Contract:**
```typescript
// Request
POST /api/v1/cma/report
Body: { location: "Downtown Dubai" }

// Response
{
  report_url: "https://cdn.example.com/reports/cma_123.pdf",
  message: "CMA report generated for Downtown Dubai"
}
```

---

### 2. Orchestrator Enhancement (`src/services/orchestrator.ts`)

**Before (v2.9):**
```typescript
case 'CMA':
  if (intent.location) {
    workflowResponse = await createCMA(intent.location);
  }
  break;
```

**After (v2.9.1):**
```typescript
case 'CMA':
  if (intent.location) {
    // Generate CMA report and get download link
    const cmaReport = await generateCMAReport(intent.location);
    console.log('[Orchestrator] CMA report generated:', cmaReport);
    
    // Create workflow response with report URL
    workflowResponse = {
      success: true,
      task_id: `cma_${Date.now()}`,
      message: cmaReport.message,
      data: {
        location: intent.location,
        report_url: cmaReport.report_url,
      },
    };
  }
  break;
```

**Key Changes:**
- Calls `generateCMAReport()` instead of `createCMA()`
- Includes `report_url` in workflow response data
- Enhanced logging for debugging

---

### 3. Store Schema Update (`src/store/commandStore.ts`)

**Added RequestMetadata Interface:**
```typescript
export interface RequestMetadata {
  location?: string;       // For CMA and market reports
  topic?: string;          // For social posts
  confidence?: number;     // Intent detection confidence
  report_url?: string;     // CMA report download link
  [key: string]: any;      // Allow other fields
}
```

**Updated Request Interface:**
```typescript
export interface Request {
  id: string;
  title: string;
  status: RequestStatus;
  type: RequestType;
  timestamp: number;
  error?: string;
  metadata?: RequestMetadata;  // Now typed!
}
```

### 4. UI Enhancement (`src/pages/Requests.tsx`)

**Download Button Display:**
```tsx
{/* CMA Report Download Link */}
{req.type === 'CMA' && req.metadata?.report_url && req.status === 'Complete' && (
  <a
    href={req.metadata.report_url}
    target="_blank"
    rel="noopener noreferrer"
    className="mt-3 inline-flex items-center gap-2 px-3 py-2 bg-blue-50 text-blue-600 rounded-lg text-xs font-medium hover:bg-blue-100 transition-colors border border-blue-200"
  >
    <Download className="w-4 h-4" />
    Download CMA Report
  </a>
)}
```

**Conditions for Display:**
1. Request type must be `'CMA'`
2. `report_url` must exist in metadata
3. Status must be `'Complete'`

**Styling:**
- Blue background with darker blue text
- Download icon from lucide-react
- Opens in new tab (target="_blank")
- Hover effect (lighter blue)
- Responsive font size (text-xs)

---

### 5. Environment Configuration (`.env.example`)

**Added Variable:**
```env
# API Mode
# Set to 'true' to use real backend APIs for workflows (CMA, reports, social posts)
# Set to 'false' to use mock responses (faster, no backend required)
VITE_USE_REAL_API=false
```

**Usage:**
- **Development:** Set to `false` (default) for fast mock responses
- **Staging:** Set to `true` to test with real backend
- **Production:** Set to `true` for live CMA generation

## Flow Diagram

```
User: "Generate CMA for Downtown Dubai"
            ↓
[Intent Detection] → CMA detected, confidence 0.8
            ↓
[Orchestrator] → Call generateCMAReport("Downtown Dubai")
            ↓
[Workflow API] → Check VITE_USE_REAL_API
            ↓
    ┌───────┴───────┐
    │               │
Mock Mode      Real Mode
    │               │
    │               ↓
    │     POST /api/v1/cma/report
    │               ↓
    │     Backend generates PDF
    │               ↓
    └───────┬───────┘
            ↓
Return: {
  report_url: "/mock-reports/CMA_Downtown_Dubai.pdf",
  message: "Mock CMA report generated"
}
            ↓
[Store] → Save request with metadata.report_url
            ↓
[Requests Page] → Display "Download CMA Report" button
            ↓
User clicks → Opens PDF in new tab
```

## Known Limitations

1. **Mock URLs Are Not Real:** Mock mode generates fake PDF paths that won't actually download
   - *Workaround:* Set VITE_USE_REAL_API=true when backend is ready

2. **No Progress Updates:** CMA generation is a single API call with no intermediate status
   - *Future:* Add polling for long-running CMA tasks

3. **No Report Preview:** Users must download to view
   - *Future:* Add inline PDF viewer or thumbnail preview

4. **Single Download Link:** Multiple versions not supported
   - *Future:* Track report versions and allow re-generation

## Developer Notes

### Why Mock by Default?
- Faster development (no backend dependency)
- Works offline
- Predictable results for UI testing
- Reduces API costs during development

### Why Separate Mock Function?
- Cleaner code separation
- Easier to test mock behavior independently
- Can be reused for unit tests
- Explicit about what's being mocked

### URL Format
Mock URLs use this pattern:
```
/mock-reports/CMA_{sanitized_location}_{timestamp}.pdf
```
- Sanitized: Spaces replaced with underscores
- Timestamp: Ensures uniqueness
- Example: `/mock-reports/CMA_Downtown_Dubai_1699123456789.pdf`
