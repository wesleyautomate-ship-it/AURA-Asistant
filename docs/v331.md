## 1) Feature outcome (what to build)

**Goal:** A GPT-style **Agentic Chat** page (like Cursor/Windsurf) that:

* Streams responses.
* Uses **RAG** to answer from listings, company docs/policies, and product help.
* Can **call platform tools** (brochure/CMA/social post/email draft, etc.) via the existing backend pipeline.
* Stores **chat threads** (session history) and surfaces them in a left rail.
* Has a **voice hook** (button) that will feed the chat input using the already working transcription service (we won’t implement TTS here).
* All changes are **additive** and keep the current look/feel.

## 2) Backend additions (FastAPI)

Create a minimal, additive **chat orchestrator** that reuses your intelligence plumbing.

**New endpoint (SSE or polling fallback):**

* `POST /api/v1/intelligence/chat`

  * Request: `{ thread_id?: string, message: string, metadata?: { source: 'chat_ui', user_context?: {...} } }`
  * Behavior:

    * Persist inbound message to a new `chat_threads` / `chat_messages` schema (SQLite).
    * Run **intent detection** (Gemini) to decide: “answer only” vs “answer + tool”.
    * If tool needed, call the appropriate existing pipeline (e.g., brochure/CMA generator) and return a **tool action** event with the spawned `task_id` and later the `content_id`.
    * Always stream back assistant messages + progress steps (SSE). Provide a polling fallback.
  * Response stream events (shape):

    * `thinking` (optional)
    * `retrieval` (docs/listings matched)
    * `message` (assistant text chunks)
    * `tool_invocation` (name, args, spawned `task_id`)
    * `tool_result` (final `content_id`/link if available)
    * `final` (done flag, tokens/time)

**New models / tables (SQLite):**

* `chat_threads(id, title, created_at, updated_at, user_id?)`
* `chat_messages(id, thread_id, role['user'|'assistant'|'system'], text, tokens_in?, tokens_out?, created_at)`
* Simple repository layer (keep it tiny and aligned with current SQLAlchemy style).

**RAG integration (non-destructive):**

* Reuse `rag_service.py`. Add a small helper that:

  * Accepts `{ message, user_id }` and returns top-k passages from:

    * Listings (from DB)
    * Company docs/policies (vector index)
    * Product docs/help (vector index)
  * Deliver retrieved chunks as a `retrieval` event before or during generation.

**Tool registry (server-side “function calling” shim):**

* Implement a simple registry mapping intents to existing actions:

  * `create_brochure(listing_id)` → call your `/generate` with `content_type: "PROPERTY_BROCHURE"`
  * `create_cma(area_or_listing)` → similar
  * `create_social_post(context)` → similar
  * `create_email_draft(context)` → similar
* The chat orchestrator selects and invokes the mapped tool, then emits the `tool_invocation` event.

**Auth & dev mode:**

* Respect your dev auth bypass if `DISABLE_AUTH=true`.
* Follow the existing style for request logging and error mapping.

## 3) Frontend additions (React + Zustand)

**New route (align with current router style):** `/chat/console`

* Do **not** replace the existing Chat page cards. Add a **“Open Console”** action there that routes to this console.
* Keep the existing design language (padding, cards, shadows). This is an **upgrade**, not a redesign.

**New components (minimal & composable):**

* `src/pages/ChatConsole.tsx`

  * Three regions:

    1. **Left rail**: Thread list (recent threads with search)
    2. **Message pane**: GPT-style messages with streamed assistant output
    3. **Right rail (collapsible)**: Context panel showing RAG matches and tool suggestions
  * Input row: text box, `Send`, `🎤` voice hook (click → open existing mic/transcription UI and paste text into input)
  * Session title inline editable (default: first user message snippet)
* `src/store/chatStore.ts`

  * Holds `threads`, `messagesByThread`, `currentThreadId`, streaming state
  * Methods: `createThread`, `sendMessage`, `receiveChunk`, `appendToolEvent`, `loadThreads`, `renameThread`
* `src/services/api/chatApi.ts`

  * `startChat(threadId?, message)` returns an SSE reader
  * Polling fallback if SSE unavailable
* `src/components/chat/Message.tsx`, `MessageList.tsx`, `ThreadList.tsx`, `ContextPanel.tsx`, `ToolChips.tsx`

  * Keep styling consistent with your existing components (use your utility classes and spacing).
* **Navigation:** from the current Chat page card (“AI Command Center & Chat”), add a **primary button** “Open Console” that routes to `/chat/console`.

**Streaming UX & state:**

* Show animated dots while `thinking`.
* Render a small “Using context from: …” list when `retrieval` events arrive (with clickable chips to preview the source).
* When a `tool_invocation` event arrives, show a non-blocking toast with a “View Task” link (or “Open Content” once `content_id` is emitted).

**Voice hook (front-end only):**

* Place a 🎤 button near the input: when clicked, open the **existing** mic/transcription workflow; on result, paste transcript into the input. No TTS.
