## 📝 Documentation Standards

### File Naming
- Use kebab-case for file names (e.g., `api-endpoints.md`)
- Use descriptive, clear names that indicate content
- Group related files in subdirectories

### Content Structure
- Start with a clear title and description
- Use consistent heading hierarchy (H1 → H2 → H3)
- Include table of contents for longer documents
- Add examples and code snippets where appropriate

### Maintenance
- Keep documentation current with code changes
- Update CHANGELOG.md for all releases
- Review and update architecture docs quarterly
- Verify all links and references regularly
